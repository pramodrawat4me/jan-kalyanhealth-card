1. Project Overview
Jan Arogya is a desktop-based hospital discount card management system. It enables registered partner operators to manage customer health cards, generate printable PDF cards with embedded QR codes, and access a global directory of empanelled hospitals — all from a Windows/macOS desktop application. The backend exposes a REST API consumed by both the desktop app and the Admin web portal.

1.1 Objectives
Provide partners a fast, offline-capable desktop interface for card management.
Issue unique health card IDs and generate printable cards in PDF format.
Embed QR codes on printed cards that display empanelled hospitals when scanned.
Admin web portal to create, activate, and deactivate partner accounts.
Data isolation: each partner sees only their own customers; hospital list is global.

2.2 Electron App Architecture (IPC Pattern)
The Electron shell has two processes: Main Process (Node.js) and Renderer Process (React). Communication uses IPC (Inter-Process Communication). The renderer never directly calls Node.js APIs — all privileged operations go through preload scripts.

Renderer (React UI)
  ↕  window.electronAPI.invoke('channel', payload)   ← preload bridge
Main Process (Node.js)
  ↕  ipcMain.handle('channel', handler)
  → HTTPS call to Backend API
  → Return response to Renderer

6. Card ID Generation & PDF Card
6.1 Card ID Format
The Card ID (आई.डि.) is auto-generated on the server when a new customer record is created.
Format: YYYYMMDD + 6-digit random number
Example: 2026-06-19 + 593841  =  20260619593841

6.2 Server-Side Generation (Node.js)
function generateCardId() {
  const today = new Date();
  const yyyy  = today.getFullYear();
  const mm    = String(today.getMonth() + 1).padStart(2, '0');
  const dd    = String(today.getDate()).padStart(2, '0');
  const rand  = Math.floor(100000 + Math.random() * 900000); // 6 digits
  return `${yyyy}${mm}${dd}${rand}`;
}
// Always check DB uniqueness before saving — retry if collision

6.5 PDF Generation — Server Code (Node.js + Puppeteer)
const puppeteer = require('puppeteer');
const QRCode    = require('qrcode');

async function generateCardPDF(customer) {
  const qrUrl  = `https://janarogya.in/hospitals?card=${customer.card_id}`;
  const qrData = await QRCode.toDataURL(qrUrl, { width: 128 });
  const html   = renderCardTemplate(customer, qrData); // HTML template
  const browser = await puppeteer.launch({ args: ['--no-sandbox'] });
  const page    = await browser.newPage();
  await page.setContent(html, { waitUntil: 'networkidle0' });
  const pdfBuffer = await page.pdf({
    format: 'A4', printBackground: true,
    margin: { top: '10mm', bottom: '10mm', left: '10mm', right: '10mm' }
  });
  await browser.close();
  return pdfBuffer; // Stream to client or save to S3
}

6.6 QR Code — Public Scan Endpoint
The QR code on every printed card encodes the following URL:
https://janarogya.in/hospitals?card=<card_id>
When scanned by hospital staff or patient, GET /cards/public/:card_id returns a mobile-optimised HTML page showing:
Customer name and card validity status (valid / expired).
Complete list of empanelled hospitals with name, address, phone, and discount details.
No login required — fully public endpoint.
ℹ  Rate-limit this public endpoint to 200 requests/minute per IP to prevent abuse. Never include sensitive PII (Aadhaar, address) in the QR URL or scan result page.

8. Security Requirements
Area
Requirement
Token Storage
Use Electron safeStorage (OS keychain-backed) — NEVER localStorage or plain files
JWT Expiry
Access token: 8 hours; Refresh token: 30 days; rotate on each refresh
Password Hashing
Bcrypt with cost factor minimum 12
Data Isolation
EVERY customer query must include WHERE partner_id = <authenticated_id> enforced at API layer
Admin Separation
Admin JWT scope != partner JWT scope; middleware checks role on every admin route
Aadhaar Storage
AES-256-GCM encryption at rest; display only last 4 digits in UI
File Upload
Validate MIME type server-side; max 2 MB; rename to UUID; strip EXIF; reject executables
Rate Limiting
Login: 5 attempts per 15 min per IP; QR public: 200/min per IP
HTTPS Only
All API traffic over TLS 1.2+; HTTP requests redirected to HTTPS
Content-Security-Policy
Set CSP in Electron BrowserWindow; disable nodeIntegration in renderer; use contextIsolation
Auto-Update Signing
Sign Electron app with code-signing certificate; verify update signature before install

9.3 Desktop App Error Handling
Network errors (no internet): show toast notification 'No internet connection. Please check your network.'
401 response: auto-refresh token once; if refresh fails, logout and redirect to Login screen.
403 ACCOUNT_DEACTIVATED: show modal 'Your account has been deactivated. Please contact the administrator.' and force logout.
500 server error: show generic 'Something went wrong. Please try again.' toast with retry button.
File too large: validate size client-side before upload; show inline error below photo field.
